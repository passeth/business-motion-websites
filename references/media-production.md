# 이미지·영상·프리젠테이션 제작

## 제작 전에 자산의 역할을 정한다

| 역할 | 적합한 매체 | 기획 포인트 |
|---|---|---|
| 브랜드 분위기 | 짧은 루프, 넓은 이미지 | 카피 여백·명도·끊김 없는 경계 |
| 업무/제품의 실재성 | 제공받은 실제 사진·화면·촬영 | 출처·공개 허용·설명 일치 |
| 절차·데이터 관계 | SVG, HTML 모션 그래픽, Hyperframes | 순서·객체·상태·근거 |
| 미래 가능성 | 생성 이미지·영상, 개념 시각화 | 콘셉트임을 구분, 실적처럼 오인 금지 |
| 프로그램 비교 | 텍스트·도표 중심의 프리젠테이션 | 차이·진입 조건·산출물, 한 장면의 정보량 |

스톡 이미지 몇 장을 반복 배치하는 대신 자산별 역할·비율·크롭·조명을 계획한다. 다만 모든 자산을 새로 생성할 필요는 없다. 이미 승인된 유용한 자료를 활용하고 부족한 장면만 제작한다.

## 이미지 제작 루프

1. 자산 목록에 페이지, 설명할 내용, 비율, 데스크톱/모바일 크롭, 제목이 놓일 영역을 적는다.
2. 공통 시각 문법을 정의하고 소재·거리·구도를 달리해 다양성을 만든다.
3. 대표 이미지부터 생성·확인한 후 변형을 확장한다. 사용자의 원본 이미지와 실제 제품 특징을 보존한다.
4. 원본과 웹용 최적화 파일을 구분한다. 표시 크기에 맞는 해상도와 형식, width/height, 적절한 alt를 제공한다.
5. 화면 안에서 크롭·대비·본문과의 관계를 검증한다. 생성 성공만으로 납품 완료로 보지 않는다.

프롬프트 구성 예:

`역할과 전달할 개념 + 실제 대상/재질 + 구도/거리/렌즈 + 조명/색 + 카피 안전 영역 + 비율/모바일 크롭 + 제외할 로고·가짜 글자·오해 소지`

읽어야 할 제목·수치·UI는 HTML/SVG로 만든다. 생성 이미지 속 글자에 의존하지 않는다. 생성 이미지가 실제 고객 시설이나 운영 화면이 아니라면 시각 콘셉트로 구분한다. 이미지 생성·편집은 현재 제공된 도구 지침과 사용자 선택을 따른다.

## 영상 방식 선택

- 생성 영상: 실제 공간·제품·재료의 움직임과 분위기를 만드는 데 적합하다. 확보된 이미지에서 출발하면 시각 일관성을 유지하기 쉽다.
- Hyperframes 등 결정론적 HTML 렌더: 정확한 한글, 도표, 단계, 서비스 설명, 데이터 흐름에 적합하다. 편집 가능한 소스와 실제 MP4를 함께 납품한다.
- 사이트의 SVG/CSS 모션: UI와 상호작용하거나 화면 크기에 맞게 계속 변해야 하는 그래픽에 적합하다.
- 기존 영상 편집: 컷, 크롭, 속도, 음성·음악 추가가 목적일 때 사용한다.

패닝한 정지 이미지를 생성 영상이라고 설명하지 않는다. HTML 미리보기와 렌더된 MP4도 구분한다. 사용자가 특정 도구를 지정하면 우선 해당 기능을 확인하고, 불가능할 때는 바뀌는 결과를 설명한다. 도구가 없다는 이유로 임의 공급자에 유료 작업을 제출하지 않는다.

## 도구 연결의 예

다음은 후보 연결이며 필수 설치 목록이 아니다. 실제 사용 전 현재 도구 목록과 해당 기능의 스킬을 확인한다. 사용자가 지정한 공급자와 기존 자산 파이프라인을 우선한다.

| 작업 | 사용 가능한 도구의 예 | 전달할 입력과 받을 결과 |
|---|---|---|
| 이미지 생성·편집 | 기본 imagegen, 지정한 이미지 공급자 | 역할·시각 문법·참고 이미지 → 실제 이미지 파일 |
| 브랜드·공간 영상 | Topview 또는 Higgsfield의 연결된 영상 기능 | 장면·카메라·길이·시작/끝 조건 → 작업 ID·영상 원본 |
| 서비스 프리젠테이션 | Hyperframes | 확인된 사업 문구·스토리보드·자산 → 편집 프로젝트·MP4 |
| 나레이션 | ElevenLabs 등 허용된 음성 도구 | 확정 대본·발음·타이밍 → 오디오 파일 |
| 포스터·믹싱·인코딩 | FFmpeg/FFprobe 등 로컬 도구 | 확보된 파일 → 배포본·메타데이터·검증 프레임 |
| 웹 모션 | 기존 프로젝트의 SVG/CSS/JS/모션 라이브러리 | 의미 있는 상태·관계·스크롤 구간 → 반응형 인터랙션 |

공급자 API 형식·모델명·과금은 이 문서에 고정하지 않는다. 연결 도구의 현재 계약을 읽고, 결과 파일과 출처를 다음 단계에 전달한다. 설치 권한이나 인증이 없으면 로컬 구성·대본·스토리보드 등 독립 작업을 진행하고, 해당 생성 단계만 미완료로 표시한다.

## 생성 영상 운영

1. 모델·길이·비율·입력 조건을 현재 도구에서 확인한다.
2. 움직임의 원인, 카메라, 시작/끝 상태, 보존할 대상, 반복 여부를 명시한다.
3. 비동기 작업 ID와 요청 상태를 기록한다. 제출 응답이 불명확하면 기존 작업을 조회하고, 비멱등 요청을 반복 제출하지 않는다.
4. 결과를 받아 처음·중간·끝을 확인한다. 제품 왜곡, 불필요한 움직임, 루프 경계, 브랜드 일관성을 검토한다.
5. 최종 파일의 실제 길이·크기·코덱을 확인하고 포스터를 추출한다. 원본 프로젝트·프롬프트·공급자 근거는 비밀값 없이 보관한다.

## Hyperframes 프리젠테이션 루프

공식 기준: [Hyperframes 저장소](https://github.com/heygen-com/hyperframes), [공식 문서](https://hyperframes.heygen.com/docs). Hyperframes는 HTML/CSS와 탐색 가능한 애니메이션을 영상으로 렌더하는 도구다. 설치된 버전과 현재 CLI/프로젝트 계약을 확인한다. 과거에 사용한 명령이나 타임라인 등록 형식을 최신 버전의 요구로 가정하지 않는다.

작업 순서:

1. **메시지**: 한 영상이 답할 고객 질문과 핵심 결론을 정한다.
2. **스토리보드**: 장면별 메시지, 구체 객체, 모션, 실제 읽기 시간과 오디오를 배정한다. 짧은 영상에는 과한 소개·엔딩보다 하나의 설명 흐름을 유지한다.
3. **편집 소스**: 폰트·이미지·타임라인·텍스트·비율·길이를 재현 가능한 프로젝트로 보관한다. 외부 자산 로딩 실패가 렌더 결과에 영향을 주지 않게 가능한 한 로컬 자산을 사용한다.
4. **탐색 가능한 모션**: 임의 시점으로 이동해도 동일한 그림을 보여주게 구성한다. 페이지 로드 시각에만 의존하는 setTimeout, 무한 랜덤, 스크롤 리스너만으로 렌더를 제어하지 않는다. 프레임워크의 현재 타임라인 규약을 따른다.
5. **프리뷰 검증**: 장면 경계·한글 줄바꿈·폰트 로딩·도표 관계·텍스트 체류시간을 확인한다.
6. **실제 렌더**: 설치 버전의 검사/렌더 명령을 실행하고 결과 MP4를 받는다. HTML 캡처만으로 MP4 완료를 주장하지 않는다.
7. **최종 파일 검증**: 디코딩한 시작·전환·중간·끝 프레임과 연속 재생을 확인한다. 특히 타임라인 역방향 탐색, 마지막 프레임 소실, 검은 프레임, 빠진 폰트를 확인한다.
8. **갤러리 연결**: 포스터·제목·핵심 설명·관련 서비스 링크를 연결한다. 편집 프로젝트를 보관한다.

장면 예시(새 사업에 맞게 변경): 분산된 자료 → 공통 식별자와 관계 → 확인·승인 → 운영 화면. 이 예시는 설명 문법이며 다른 사업에 강제하지 않는다.

처음부터 모든 영상을 병렬 렌더하지 않는다. 대표 프로젝트 하나로 폰트·타임라인·렌더 파이프라인을 확인한 후 필요한 영상으로 확장한다. 검증한 도구 버전과 재렌더 방법을 프로젝트에 기록한다.

## 음성·배경음

- 배경 루프는 기본적으로 소리 없이 사용하고, 설명 영상은 사용자 요청·맥락에 따라 나레이션을 붙인다. 소리 있는 자동재생을 전제하지 않는다.
- 실제 장면의 정보와 내레이션을 맞춘다. 줄임말·브랜드명 발음, 장면별 호흡, 문장 길이를 확인한다. 화면 글을 과도하게 중복해서 읽지 않는다.
- 음성 스크립트와 발음 기준을 먼저 고정하면 유료 재생성을 줄일 수 있다.
- 배경음은 나레이션을 가리지 않도록 믹싱하고 장면 끝의 잘림·클리핑을 확인한다. 스트림 존재만 확인하지 말고 실제로 들어본다.
- 최종 믹싱된 MP4를 다시 디코딩·검증한다. 무음 원본을 갤러리에 잘못 연결하지 않게 파일 목록을 갱신한다.
- 접근성에 필요한 자막·텍스트 대체는 검토하되 내부 스토리보드·시간코드·제작 로그를 공개 설명란에 붙이지 않는다.
- 인증키는 서버 환경·승인된 비밀 저장소로 관리하고 HTML·JS·프로젝트 ZIP에 넣지 않는다.

## 갤러리

카드에 영상의 제목, 설명 목적, 길이, 포스터, 관련 페이지를 제공한다. 필터는 충분한 콘텐츠가 있을 때 도입한다. 비슷한 영상을 수량 채우기용으로 늘리지 않는다.

일반적으로 재생 중인 설명 영상은 하나로 제한한다. 이 규칙을 모든 video 요소에 적용해 히어로 배경과 스크롤 장면까지 멈추게 만들지 않는다. 컴포넌트/역할 단위로 제어한다. 뷰포트 인근에서 소스를 붙이고, 화면 밖·숨겨진 탭에서는 필요한 재생만 중지한다. 모든 갤러리 영상을 첫 화면에서 다운로드하지 않는다.

## 미디어 목록과 번들 검사기

기획 단계의 자산 목록은 `계획 / 제작 중 / 파일 확보 / 검증 완료` 상태와 예정 경로를 기록한다. 실제 파일이 없는 목록을 검사기에 넣어 형식적인 실패를 만들지 않는다. 실행용 manifest에는 확보한 파일을 넣고, 미제작 자산은 전체 제작 목록에서 계속 추적한다. 검사 통과가 프로젝트의 모든 자산 제작 완료를 뜻하지는 않는다.

입력 JSON의 상대 파일 경로는 목록 파일의 디렉터리를 기준으로 한다. `expectedAudio`는 영상에 음성/음악 스트림이 필요한 경우에만 true로 둔다. 무음 요구가 확정된 경우 false로 둔다. 생략하면 오디오 존재만 보고한다.

```json
{
  "assets": [
    {
      "id": "hero-loop",
      "kind": "video",
      "file": "media/hero.mp4",
      "poster": "media/hero.webp",
      "role": "brand-atmosphere",
      "expectedAudio": false,
      "maxBytes": 12000000,
      "provenance": "Generated concept; local generation record in production/hero.json"
    },
    {
      "id": "service-explainer",
      "kind": "video",
      "file": "media/service.mp4",
      "poster": "media/service.webp",
      "role": "service-explanation",
      "expectedAudio": true,
      "provenance": "Editable project in production/service"
    }
  ]
}
```

위 크기 값은 사용 예이며 보편적 권장 한도가 아니다. 실제 네트워크·표시 크기·미디어 수에 맞춰 예산을 합의한다. 검사기는 ffprobe 메타데이터, 파일·포스터 존재, 오디오 요구, 선택적 크기 예산만 확인한다. 영상의 움직임, 시각 품질, 음성 내용, 출처 권리, 모바일 재생을 보증하지 않는다. 서명 URL·인증값 대신 안정적인 내부 근거 위치를 사용한다.

# 비즈니스 이해와 콘텐츠 설계

## 원재료를 서비스 언어로 바꾸기

대상 고객이 구매를 결정할 때 확인하는 순서로 정리한다.

1. **상황**: 누가 어떤 도구로 무엇을 수행하는가.
2. **문제**: 어디서 지연·누락·재작업·판단의 어려움이 생기는가.
3. **개입**: 공급자가 무엇을 진단·설계·구현·운영하는가.
4. **산출물**: 계약 후 고객이 어떤 자료·기능·운영 체계를 받는가.
5. **검증**: 누구의 어떤 기준으로 완료를 판단하는가.
6. **전제와 경계**: 준비 자료, 연계 조건, 고객 책임, 별도 범위.
7. **다음 행동**: 상세 검토, 사례 보기, 자료 준비 또는 상담.

입력이 ‘흩어진 데이터를 연결했다’뿐이면, 실제 경험에서 데이터의 종류·연결 기준·변경 상태·업무 결과를 추출한다. 불명확한 부분은 설명을 위한 제안으로 구분한다. 사업을 더 전문적으로 보이게 하려고 수행하지 않은 역량을 붙이지 않는다.

### 문장 변환 예

- 원재료: ‘생산·구매·품질·물류를 연결했다.’
- 정리: ‘주문, 자재, 생산 실적과 출하 상태를 같은 식별자로 연결해 부서별 확인·대조 과정을 줄이는 운영 구조를 설계합니다.’
- 추가 근거: 어떤 식별자와 예외를 실제로 다뤘는지 사용자 자료에서 확인한다. 확인되지 않은 절감률은 붙이지 않는다.

‘그다음이 달라집니다’, ‘혁신을 경험하세요’처럼 무엇이 바뀌는지 없는 문장은 구체적인 활동·산출물·판단 기준으로 바꾼다. 전문성은 명사와 영어를 늘리는 것보다 작업 대상과 경계를 정확히 설명하는 데서 나온다.

## 주장 근거 표

| 필드 | 의미 |
|---|---|
| 주장 | 공개할 문장 또는 요지 |
| 유형 | 출처 사실 / 사용자 경험 / 제안 / 가상 시나리오 / 미확인 |
| 근거 | 제공 자료 위치 또는 공식 URL과 확인일 |
| 사용 위치 | 홈·서비스·사례 등 |
| 게시 조건 | 공개 허용 여부, 익명화, 수치 산정 조건 |

실제 경험은 사용자 진술임을 내부 근거에 남긴다. 고객명·로고·운영 화면·실적은 공개 사용 권한을 별도로 확인한다. 가상 사례는 페이지에서 명확히 표시하며 통계·추천사 구조화 데이터로 변환하지 않는다.

## 페이지 지도

페이지마다 아래 항목을 한 줄씩 먼저 적는다.

`slug / 방문자 질문 / 한 문장 답변 / 고유 내용 / 근거 / 시각 설명 / 관련 링크 / CTA`

선택 가능한 구조:

| 페이지 역할 | 답해야 할 질문 | 정보 구성 |
|---|---|---|
| 홈 | 우리 상황에 맞는 회사인가? | 포지션·핵심 분야·접근·대표 근거·상담 |
| 서비스/제품 목록 | 무엇을 제공하는가? | 범위별 비교·선택 조건·상세 링크 |
| 서비스 상세 | 무엇을 받고 어떻게 진행하는가? | 대상·범위·산출물·과정·검수·전제·FAQ |
| 전문 영역/솔루션 | 우리 업무를 이해하는가? | 실제 객체·흐름·예외·적용 조건 |
| 사례/적용 시나리오 | 적용 모습과 근거는? | 배경·설계 개입·산출물·검증·범위 |
| 영상/인사이트 | 방법을 빠르게 이해할 수 있나? | 짧은 설명·미디어·관련 서비스·다음 행동 |
| 회사 | 누구이며 무엇을 책임지는가? | 확인된 경험·팀/협업 구조·원칙·연락처 |
| 문의 | 무엇을 준비하고 어떻게 연락하나? | 최소 질문·실제 처리 방식·회신 경로·개인정보 |

각 사업에 필요한 것만 선택한다. 제품이라면 가격·통합·사용법·문서가 더 중요할 수 있다. 브랜드 사이트에 무조건 여덟 페이지를 만들지 않는다. 상세 내용 없이 비슷한 랜딩 페이지를 양산하지 않는다.

## 서비스 프로그램과 사례

프로그램은 사용자 사업에서 도출한다. 과거 프로젝트의 Discover/Connect/Augment/Evolve를 자동 복사하지 않는다. 이름보다 각 단계의 진입 조건과 종료 산출물이 구별되어야 한다.

사례는 다음 구조로 만든다:

`실제/예시 표시 → 업무 상황 → 원인/판단 기준 → 적용 내용 → 산출물 → 검증 방식 → 범위·한계 → 관련 서비스`

공개 실적이 없을 때는 구체적인 가상 입력·업무·출력을 사용하되 실제 납품 완료 화면처럼 표현하지 않는다. 수치는 예시임을 표시해도 오해하기 쉬운 ‘성과’ 헤드라인에 넣지 않는다.

필터는 탐색 수단이다. 원래 요구가 전체 탐색이면 전체를 기본값으로 유지한다. 특정 프로그램 링크가 왜 필터된 결과를 여는지 기대를 정하고, 초기 진입·새로고침·뒤로 가기·필터 해제를 일관되게 만든다. 상세 페이지와 모달 중 공유·검색·읽기 요구에 맞게 선택한다.

## 문의와 운영 언어

- 메일 초안 열기, 실제 서버 제출, 예약 링크는 다른 행동이다. 버튼과 완료 문구를 실제 동작에 맞춘다.
- 고객에게 결정에 도움이 되는 범위·조건을 설명한다. 내부 디버깅 문구, 렌더 시간코드, 스크롤 엔진 조작 안내를 본문에 노출하지 않는다.
- 기술 용어가 제품의 핵심이면 쓰되, 그 용어가 고객 업무에 미치는 의미를 연결한다.
- CTA는 해당 페이지의 다음 질문으로 이어져야 한다. 모든 링크를 상담으로 몰지 않는다.

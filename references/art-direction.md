# 프로젝트마다 다른 아트 디렉션

## 바꿀 것과 유지할 것

유지: 정보 위계, 사업 근거, 접근성, 일관된 구성 요소, 미디어 검증.
변형: 화면 밀도, 글자 크기/서체, 이미지 재료, 색·명도, 그리드, 여백의 리듬, 모션의 속도·형태.

기존 승인된 브랜드는 먼저 존중한다. 새로운 방향이 필요할 때 아래 축에서 서로 다른 선택을 조합한다. 여러 축이 같다면 이름만 다른 시안인지 점검한다.

- 편집 방식: 잡지형 / 제품 사용 중심 / 공간·장면 중심 / 데이터·도표 중심.
- 타이포: 정밀한 산세리프 / 절제된 세리프 / 혼합. 한글 본문과 영문 제목의 밀도를 함께 확인.
- 레이아웃: 비대칭 서사 / 균형 잡힌 비교 / 넓은 전경 / 촘촘한 디테일.
- 이미지: 실제 작업·제품 / 재료·공정 / 사람·환경 / 추상적 관계.
- 색채: 차분한 자연색 / 밝은 기술색 / 따뜻한 모노톤 / 강한 브랜드 대비.
- 움직임: 정돈된 전환 / 연속적인 공간 탐색 / 단계적 절차 / 정밀한 상태 피드백.

예: 바이오 서비스의 신뢰는 실험의 정확성과 사람의 검토에서, 건축 스튜디오의 신뢰는 공간·재료·프로젝트 기록에서, B2B SaaS의 신뢰는 실제 사용 흐름과 결과에서 보여줄 수 있다. 이 예시는 스타일 지시가 아니라 사업에 따라 시각 근거가 달라진다는 설명이다.

## 레퍼런스 읽기

관찰 항목: 첫 화면의 주장, 페이지 간 깊이, 탐색 경로, 근거의 위치, 섹션 대비, 이미지 크롭, 모션이 설명하는 관계. ‘예뻐 보인다’ 대신 어떤 목적에 어떤 요소가 작동하는지 기록한다.

레퍼런스는 구성 논리를 참고한다. 문구·고객 로고·실적·특징적 장면을 자기 브랜드 것으로 전용하지 않는다. 경쟁 업체의 서비스 목록을 그대로 공급 범위로 삼지 않는다.

## DESIGN.md에 기록할 내용

- 대상 고객과 원하는 인상, 피해야 할 인상.
- 토큰: 색·타입·간격·폭·선·모서리·그림자·모션 시간/이징.
- 제목/설명/근거/CTA의 위계와 모바일 변화.
- 이미지: 소재, 빛, 카메라, 구도, 표면, 금지 표현.
- 모션: 주목시킬 곳, 조용히 둘 곳, 축소/정지 상태.
- 재사용 컴포넌트와 상태: 내비게이션, 서비스 비교, 사례, 갤러리, FAQ, 문의.

고정 px·임의 색의 대량 복제보다 의미 있는 토큰과 실제 DOM 구성 요소를 사용한다. 읽어야 하는 문구·표·컨트롤을 장식 이미지에 박아 넣지 않는다.

## 첫 구현 구간

홈의 대표 장면과 내용이 많은 상세 구간을 함께 만든다. 첫 화면만 멋지고 상세가 비어 있으면 방향을 검증한 것이 아니다.

- 제목은 영상 없이도 사업의 종류와 가치를 이해시킨다.
- 설명·CTA 영역을 먼저 정하고 미디어의 안전 여백과 명도를 맞춘다.
- 모바일 크롭을 별도 검토한다. 데스크톱의 중심 크롭이 중요한 제품·사람을 자를 수 있다.
- 화면 전환은 전경/여백/도표/세부 정보의 리듬으로 만든다. 모든 섹션을 같은 카드 3개로 반복하지 않는다.
- 텍스트 선택, 키보드 포커스, 화면 확대, 한글 줄바꿈을 실제 브라우저에서 확인한다.

## 모션이 디자인을 돕는 기준

| 모션 | 목적 | 실패 신호 |
|---|---|---|
| 연결선/흐름 | 선후 관계·데이터 전달 | 장식선이 실제 관계와 다름 |
| 크기·위치 변화 | 비교·전환·주목 | 읽는 동안 레이아웃이 계속 흔들림 |
| 단계적 등장 | 정보의 읽는 순서 | 빠른 스크롤 시 본문을 놓침 |
| 루프 영상 | 맥락·분위기 | 본문 경쟁·무한 다운로드·경계 점프 |
| 스크롤 장면 | 진행에 따른 구조 이해 | 긴 빈 스크롤·사용자 조작 가로채기 |
| SVG 강조 | 중요한 규칙·승인·변화 | 전체가 계속 깜박이거나 강조가 무의미함 |

평가할 질문: 움직임을 껐을 때 설명이 사라지는가? 움직임이 켜졌을 때 더 잘 이해되는가? 첫 질문이 ‘예’, 두 번째가 ‘아니오’라면 설계를 바꾼다.
